# Как дорабатывать сайт: инструкция программисту

Проект сайта вокальной школы «Звук N». Здесь описано, как устроена сборка,
как связаны шаблоны и содержимое и на что смотреть при правках.
Общие правила проекта — в [AGENTS.md](../AGENTS.md), обзор — в [README.md](../README.md).

## 1. Технологии

- **Eleventy 3** (`@11ty/eleventy` 3.1.6, в `package.json`) — генератор сайта.
- **Nunjucks** (`.njk`) — шаблоны страниц и каркасов.
- **js-yaml** — чтение файлов содержимого `.yaml`.
- **Markdown** — статьи блога (`.md`), разметку в них тоже обрабатывает Nunjucks
  (`markdownTemplateEngine: "njk"`).
- Node-модули: `"type": "module"` в `package.json`.

Команды: `npx eleventy` (сборка), `npx eleventy --serve` (локальный сервер
с живым обновлением), `npm run clean` (удалить `_site`). Аналоги: `npm run build`,
`npm start`.

## 2. Как устроена сборка

Настройки — в `eleventy.config.js`, там почти всё уже готово:

| Настройка | Значение |
|---|---|
| `dir.input` | `src` — откуда берутся шаблоны и содержимое |
| `dir.includes` | `src/_includes` — каркасы и партиалы |
| `dir.data` | `src/content` — папка данных (содержимое сайта) |
| `dir.output` | `_site` — готовый сайт |
| `templateFormats` | `njk`, `md`, `html` |
| `markdownTemplateEngine`, `htmlTemplateEngine` | `njk` |

Важные места в конфиге:

1. **Чтение YAML.** `addDataExtension("yaml,yml", …)` разбирает файлы через js-yaml.
   Папка данных — это `src/content`, поэтому **имя файла = имя данных**:
   `site.yaml` → `site`, `home.yaml` → `home`, `blog.yaml` → `blog`,
   `zanyatiya.yaml` → `zanyatiya`. Исключение — имя с дефисом
   (`o-pedagoge.yaml`), к нему обращаются через фильтр `pageData` (см. ниже).
2. **Сборка страниц из папки данных.** Папка данных по умолчанию не собирается
   как страницы: Eleventy заносит `src/content/**` в список игнорируемых.
   В конфиге этот ignore снимается обработчиком `eleventy.ignores` — иначе
   статьи блога `src/content/posts/*.md` не собрались бы в отдельные страницы.
3. **Статические файлы** копируются как есть (`addPassthroughCopy`):
   `src/assets` → `assets/`, `static/` → корень `_site/` (картинки, шрифты),
   `admin/` → `admin/` (панель управления).

## 3. Ссылки и фильтры

### Ссылки без `.html`

В содержимом и шаблонах внутренние ссылки пишутся без расширения:
`/zanyatiya`, `/kontakty#zayavka`, `/politika`. Фильтр `| url` приводит их
к рабочему виду.

Что делает `url` (`eleventy.config.js`):

- внешние и служебные адреса (`https://`, `http://`, `mailto:`, `tel:`,
  `data:` и ссылки-якоря `#…`) не трогает — они уходят как есть;
- у адреса вида `/kontakty#zayavka` отрезает якорь и возвращает его
  в конце результата;
- убирает ведущий слэш: `/zanyatiya` → `zanyatiya`;
- если у пути уже есть расширение (`.jpg`, `.html`, `.css` и т.п.) — ничего
  не добавляет;
- иначе дописывает `.html`: `/zanyatiya` → `zanyatiya.html`,
  `/kontakty#zayavka` → `kontakty.html#zayavka`.

Так пути получаются **относительными**, и сайт открывается двойным кликом
по файлу в `_site` — без веб-сервера (см. раздел 9).

### Остальные фильтры

| Фильтр | Что делает | Пример |
|---|---|---|
| `merge` | Глубокое слияние объектов (см. раздел 5) | `home \| merge('' \| pageData('home-v2'))` |
| `pageData` | Доступ к файлу содержимого, имя которого содержит дефис. Первый аргумент (слева от `\|`) не используется | `'' \| pageData('o-pedagoge')` |
| `get` | Значение по ключу: `obj[key]`, если объекта нет — `undefined` | `data \| get('title')` |
| `num` | Нумерация в два знака: `1` → `01` | `loop.index \| num` |
| `ruDate` | Дата по-русски: `2026-09-15` → «15 сентября 2026 г.» (невалидное значение возвращается как есть) | `post.date \| ruDate` |
| `sortPosts` | Статьи от новых к старым (копирует массив, оригинал не меняет) | `collections.posts \| sortPosts` |
| `datakeys` | Отладка: список ключей контекста через запятую | `'' \| datakeys` |

## 4. Цепочка «страница → каркас → партиал»

**Главная:**

```
src/pages/index.njk
  └─ frontmatter: layout: layouts/layout-main.njk, permalink: /index.html, active, selfHref
  └─ тело: выбирает вёрстку по site.mainVariant
       {% if v == '2' %}{% include "home-v2.njk" %}
       {% elif v == '3' %}{% include "home-v3.njk" %}
       {% else %}{% include "home-v1.njk" %}
src/_includes/layouts/layout-main.njk   ← каркас: шапка, меню, подвал, <title>, css/js
  └─ содержит {{ content | safe }} — сюда попадает вёрстка главной
```

Каркас по умолчанию подключает `v{{ site.mainVariant }}.css`; поле `style`
в frontmatter страницы его переопределяют — этим пользуются страницы
просмотра вариантов (`variant-1.njk`, `variant-2.njk`, `variant-3.njk`
с `style: v1.css` … `v3.css`).

**Внутренние страницы:**

```
src/pages/o-pedagoge.njk
  └─ layout: layouts/layout-inner.njk, permalink: /o-pedagoge.html, active, title, description
  └─ тело: разметка страницы, данные — {% set P = '' | pageData('o-pedagoge') %}
src/_includes/layouts/layout-inner.njk   ← каркас внутренних страниц (site.css)
```

Тот же принцип у `zanyatiya.njk`, `kontakty.njk`, `blog.njk`, `politika.njk`
(данные берутся напрямую: `zanyatiya`, `kontakty`, `blog`, `politika`).
Страница сравнения вариантов — `variants.njk` (каркас `layout-inner`).

**Статья блога:**

```
src/content/posts/*.md (frontmatter: layout: layouts/layout-post.njk)
  └─ src/_includes/layouts/layout-post.njk
       └─ layout: layouts/layout-inner.njk   ← общий каркас
       └─ {% include "post.njk" %}           ← разметка статьи
```

Каркасы ожидают из frontmatter: `title`/`metaTitle`, `description`, `active`
(какой пункт меню подсветить), `bodyClass`, `selfHref` (для главных),
а `layout-main` дополнительно — `style` (какой css подключить) и
`variantNumber` (номер варианта, он печатается в подвале; без него берётся
`site.mainVariant`).

## 5. Варианты главной

- `src/content/home.yaml` — **базовое** содержимое главной.
- `src/content/home-v2.yaml`, `home-v3.yaml` — **только отличия** для
  вариантов 2 и 3. Всё, чего в них нет, берётся из `home.yaml`.
- Переключение — `src/content/site.yaml`, поле `mainVariant: 1 | 2 | 3`.

Слияние происходит фильтром `merge` (функция `deepMerge` в конфиге), дважды —
в каркасе и в самой вёрстке варианта:

```njk
{%- if variant == 'v2.css' %}{% set H = home | merge('' | pageData('home-v2')) %}
{%- elif variant == 'v3.css' %}{% set H = home | merge('' | pageData('home-v3')) %}
{%- else %}{% set H = home %}{% endif %}
```

Правила `deepMerge`:

- **массивы заменяются целиком** — если отличается хоть один пункт списка,
  список в файле варианта пишется полностью (иначе недостающие элементы
  просто пропадут);
- **объекты сливаются по ключам** — общие ключи дополняются, лишние берутся
  из базового файла;
- примитивы (строки, числа) заменяются;
- `undefined`/`null` в дополнении игнорируются.

Файлы вариантов `variant-1.njk`/`variant-2.njk`/`variant-3.njk` показывают
свой вариант напрямую (минуя `mainVariant`), `variants.njk` — страница
сравнения всех трёх.

## 6. Как добавить новую страницу

1. **Содержимое** — `src/content/<имя>.yaml`. Имя файла станет именем данных
   в шаблонах (`<имя>`); для имени с дефисом используйте `pageData`.
2. **Шаблон** — `src/pages/<имя>.njk` с frontmatter:

   ```njk
   ---
   layout: layouts/layout-inner.njk
   permalink: /<имя>.html
   active: /<имя>
   title: 'Заголовок вкладки'
   description: 'Описание для поисковиков'
   ---
   {%- set D = <имя> %}
   <section class="page-hero"> … </section>
   ```

   Разметку повторяйте от существующей страницы-образца, данные подставляйте
   из YAML; тексты с разметкой выводите через `| safe`, ссылки — через `| url`.
3. **Пункт меню** — добавьте в `src/content/site.yaml`, раздел `menu`
   (`title` + `href: /<имя>`, без `.html`). Пункт появится в шапке, меню
   и подвале. Страницу можно не добавлять в меню — тогда она просто будет
   существовать по адресу.
4. Соберите (`npx eleventy`) и откройте `_site/<имя>.html`.

Чтобы убрать страницу из меню — удалите пункт из `site.yaml`; чтобы убрать
страницу совсем — удалите шаблон (и, если не нужен, файл содержимого).

## 7. Блог

- **Страница со списком** — `src/pages/blog.njk`, тексты шапки и блока CTA
  в `src/content/blog.yaml`.
- **Статьи** — markdown-файлы в `src/content/posts/` (один файл = одна статья).
  Frontmatter:

  ```yaml
  ---
  layout: layouts/layout-post.njk
  tags: posts                      # создаёт коллекцию collections.posts
  permalink: "/{{ page.fileSlug }}.html"   # адрес = имя файла (без .md)
  title: Заголовок статьи
  titleAccent: "часть заголовка для выделения"   # необязательно
  category: Психология
  readingTime: 5 минут чтения
  description: "Описание для поисковиков"
  active: /blog                    # подсветка пункта меню
  date: 2026-09-15
  excerpt: Краткое описание для карточки в списке
  image: assets/img/имя.jpg        # без ведущего слэша
  imageAlt: Описание картинки
  ---
  ```

- **Список собирается сам:**

  ```njk
  {% for post in collections.posts | sortPosts %}
  ```

  Карточка использует `post.url`, `post.data.title`, `post.data.excerpt`,
  `post.data.image`, `post.data.category`, `post.date | ruDate`.
- **Статья собирается в отдельную страницу** (`<имя-файла>.html`) через
  `layouts/layout-post.njk` → `post.njk`; тело статьи подставляется в
  `{{ content | safe }}`.
- Новая статья появляется в списке автоматически — править `blog.njk` не нужно.
- В `src/content/blog.yaml` есть раздел `upcoming` — карточки «Статья
  готовится» (без ссылки на страницу). Это обычные данные в YAML, они
  выводятся в том же списке после опубликованных статей.
- Особенность: `src/content` — папка данных, и сборка `.md` из неё разрешена
  отдельной строкой в `eleventy.config.js` (см. раздел 2). Не удаляйте её.

## 8. Стили, скрипты, картинки

- `src/assets/css/v1.css`, `v2.css`, `v3.css` — главные страницы по вариантам;
  `src/assets/css/site.css` — внутренние страницы. Подключаются в каркасах
  с `?v=17` в запросе (версия для сброса кеша браузера — при правке стилей
  её стоит увеличить).
- `site.css` импортирует шрифты из `../fonts/fonts.css` — файл лежит
  в `static/assets/fonts/` и копируется на сайт как есть.
- `src/assets/js/site.js` — общий скрипт: шапка при скролле, меню-бургер,
  появление блоков, счётчики, год в подвале и форма на странице «Контакты»:
  `form[data-lead]` при отправке собирает поля по их `name` и открывает
  Telegram (`TG_HANDLE = "natlyone"` прямо в скрипте). Поэтому **`id` и `name`
  полей формы не менять** (см. комментарий в `src/pages/kontakty.njk`).
- Картинки — `static/assets/img/`, шрифты — `static/assets/fonts/`; папка
  `static/` копируется в корень `_site`, поэтому путь вида
  `assets/img/файл.jpg` работает.
- Панель управления копируется из `admin/`.

## 9. Правило: только относительные пути

Ссылки и пути к картинкам пишутся **без ведущего слэша**:

- ссылка — `/zanyatiya` в содержимом, фильтр `| url` превратит её в `zanyatiya.html`;
- картинка — `assets/img/файл.jpg` (в YAML и в шаблонах, желательно через `| url`).

Абсолютный путь `/assets/img/файл.jpg` при открытии файла двойным кликом
(`file://`) уходит в корень диска, и картинка/ссылка ломается — хотя на
веб-сервере всё выглядит правильно. Проверяйте новый код именно так:
откройте страницу из `_site` в браузере напрямую, без `--serve`.

## 10. Панель управления (Decap CMS)

- `admin/index.html` — подключает Decap CMS (unpkg) и виджет входа
  Netlify Identity; `admin/config.yml` — описание всех полей панели.
- `backend: git-gateway`, ветка `main` — панель рассчитана на **опубликованный
  сайт** (хостинг, связанный с репозиторием GitHub): вход по адресу сайта
  + `/admin/`. Локально в `_site` панель открывается, но войти в неё не получится.
- Язык панели — русский (`locale: ru`).
- Публикация сайта и включение входа в панель описаны в
  [docs/КАК-ОПУБЛИКОВАТЬ.md](КАК-ОПУБЛИКОВАТЬ.md) — там же адрес опубликованного
  сайта и порядок включения Netlify Identity.
- Фотографии: `media_folder: static/assets/img` (куда складывать),
  `public_folder: "/assets/img"` (как записывать путь в YAML).

### Как добавить поле в панель

1. Найдите в `config.yml` нужную коллекцию → файл (`file:`) и добавьте поле:

   ```yaml
   - { name: priceNote, label: Подпись под ценой, widget: string }
   ```

   Типичные `widget`: `string`, `text`, `boolean`, `select`, `list`, `object`,
   `image`, `markdown`, `datetime`, `hidden`.
2. Если поле техническое — заводите его с `hidden` и `default` (так сделаны
   `layout`, `tags`, `permalink`, `active` у статей блога).
3. В шаблоне новое поле используйте как обычные данные из YAML.
4. После правки `config.yml` обновите страницу панели (если не подхватилось —
   перезагрузите её с очисткой кеша браузера).

> **Важно.** Панель при сохранении записывает файл только из полей,
> описанных в `config.yml`. Поле, которого нет в конфиге, **будет стёрто**
> при первом же сохранении этого файла через панель — даже если оно есть
> в YAML и работает на сайте. Поэтому любое новое поле сначала описывается
> в `config.yml`, и только потом используется.

То же касается полей, добавленных руками в YAML: сначала добавьте их
в конфиг панели, иначе правка владельца в панели их удалит.

## 11. Как проверять правки

1. **Сборка без ошибок:** `npx eleventy`. Самая частая причина сбоя —
   ошибка YAML (см. раздел 12); скрипт `1-СОБРАТЬ-САЙТ.command` печатает
   подсказку в этом случае.
2. **Сверка с оригиналом.** Разметка страниц должна совпадать с оригиналом,
   различия допустимы только в ссылках, переносах строк и отступах:

   ```bash
   diff <(sed 's/^[[:space:]]*//' "путь/к/оригиналу/страница.html" | grep -v '^$') \
        <(sed 's/^[[:space:]]*//' _site/страница.html | grep -v '^$')
   ```

   Оригинал: `../restored/Default Project/zvukn-landing`.
3. **Проверка ссылок.** Полезно прогнать скрипт, который обходит все HTML
   в `_site` и сверяет внутренние `href`/`src` с реально существующими
   файлами — такая проверка битых ссылок по всем страницам уже выполнялась
   для этого проекта и её стоит повторять после крупных правок.
4. **Открыть результат двойным кликом** по `_site/index.html` (без сервера),
   пройти по меню все страницы, проверить картинки и, если меняли
   `site.yaml`, — переключение `mainVariant: 1 / 2 / 3` и страницы
   `variant-1/2/3.html`.

## 12. Частые ловушки

- **YAML и двоеточие.** Строка с двоеточием внутри обязана быть в кавычках,
  иначе сборка падает:

  ```yaml
  metro: 'Метро: Звенигородская'    # правильно
  metro: Метро: Звенигородская      # ошибка парсинга
  ```

- **Комментарии в Nunjucks** — только `{# … #}`. HTML-комментарий `<!-- … -->`
  в шаблоне останется в готовой странице; `//` и `/* */` в `.njk` — это не
  комментарии.
- **Разметка в текстах.** Переносы `<br>`, выделения `<span class="it gold">…</span>`
  и любая другая разметка в данных выводятся через `| safe`, иначе Nunjucks
  экранирует их и на сайте видно текст тегов.
- **Кнопка меню (бургер)** — ровно три полоски: `<i></i><i></i><i></i>`
  в `layout-main.njk` и три `<span></span>` в `layout-inner.njk`. Менять
  их количество нельзя — на это завязаны стили и состояние меню.
- **Путь к картинке** — без ведущего слэша (`assets/img/…`, см. раздел 9).
  После загрузки фото через панель сверьте, что путь записан именно так.
- **Не править `_site/`** — любая сборка перезаписывает эту папку.
- **Не трогать оригинал** `../restored/Default Project/zvukn-landing` —
  это эталон «как было», по нему делается сверка.
- **Классы и имена файлов стилей не переименовывать** — вид сайта на них
  завязан; `eleventy.config.js` менять только если действительно нужен новый
  фильтр.
